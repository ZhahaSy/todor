# 测试代码生成

为生成的代码编写单元测试、组件测试、集成测试。

## 前置检查
读取代码生成报告、改动点文档,检查测试框架配置

## 执行步骤

### 1. 识别测试框架
检查项目使用的测试工具(Jest/Vitest/Cypress/Playwright等)

### 2. 分析测试需求
**单元测试**: utils、services、hooks、纯函数、store
**组件测试**: 渲染、交互、Props、条件渲染、事件
**集成测试**: API调用流程、页面流程、多组件协作
**E2E测试**: 完整用户流程、跨页面操作

### 3. 生成测试代码
按文件类型生成对应测试:
- utils → `__tests__/*.test.ts` (AAA模式: Arrange/Act/Assert)
- services → Mock外部依赖,测试API调用
- hooks → 使用 renderHook测试
- 组件 → 测试渲染、交互、Props变化
- 页面 → 集成测试,含路由和完整流程

### 4. 测试配置
如缺少配置,生成 jest.config.js 和 setupTests.ts

### 5. 运行测试
尝试运行 `npm test` 和 `npm test -- --coverage`

### 6. 生成报告
创建 `test-report.md`:
- 统计: 测试文件数、用例数、覆盖率
- 文件清单: 源文件与测试文件对应
- 运行结果
- 需人工补充的测试

## 输出示例
```
✅ 测试代码生成完成
📊 测试文件{N}个, 用例{M}个(单元{X}, 组件{Y}, 集成{Z})
📝 测试报告: test-report.md
💡 下一步: npm test && /spec.review 代码审查
📋 查看进度: /spec.status
```

## 最佳实践
1. 使用清晰的describe和it描述
2. AAA模式结构化测试
3. Mock外部依赖,不Mock被测代码
4. 每个测试独立,不依赖执行顺序
5. 核心逻辑100%,整体80%+覆盖率
6. 使用data-testid而非类名或文本

## 注意事项
1. 不过度测试框架功能
2. 测试用户行为而非实现细节
3. 一个用例只测一个点
4. 保持测试简单,及时更新
