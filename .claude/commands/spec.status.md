# 工作流状态查看

快速了解当前工作流进度、项目信息和下一步操作。

## 重要说明

⚠️ **首次执行时的行为**:
- 如果 `.spec/feature/` 和 `.spec/bugfix/` 目录不存在或为空，会提示"当前没有活跃的工作流"
- 这是正常现象，说明还没有开始任何工作流
- 命令会显示如何开始第一个工作流的指引

## 数据来源
- **工作流进度**: 从 `.spec/feature/` 或 `.spec/bugfix/` 目录结构读取
- **详细进度**: 从 `.spec/*/.meta/progress.json` 读取（由 `/spec.utils.progress` 自动维护）
- **项目统计**: 从实际文件系统扫描（文件数量、代码行数等）
- **知识库状态**: 从 `.spec/knowledge/` 读取（组件、API、函数等统计）

## 显示内容

### 1. 工作流基本信息
- 工作目录: `.spec/feature/{YYYY-MM-DD}-{name}/` 或 `.spec/bugfix/{YYYY-MM-DD}-{name}/`
- 需求类型: feature | bugfix
- 创建时间和持续时间
- 当前阶段和整体进度

### 2. 阶段完成状态

**单项目模式**:
```
[✓] 需求处理 - prd/
[✓] 技术方案 - tech/
[→] 代码生成 - code-changes.log (进行中)
[ ] 测试生成 - test-report.md
[ ] 代码审查 - code-review/
[ ] 需求归档 - archive-summary.md
```

**多项目模式**:
```
[✓] 需求处理 - prd/
[✓] 项目协调 - coordination/
[→] 项目开发 (2/3完成)
    [✓] backend  - 100%
    [✓] frontend - 100%
    [→] admin    - 60% (代码生成中)
[ ] 集成验证
[ ] 需求归档
```

**Bugfix模式**:
```
[✓] 问题分析 - bug-analysis.md
[✓] 问题定位 - bug-location.md
[→] 修复方案 - fix-solution.md (进行中)
[ ] 代码修复
[ ] 测试验证
[ ] 归档
```

### 3. 项目统计信息
- **知识库状态**:
  - 组件数量、API数量、函数数量、页面数量
  - 最后更新时间
  - 是否需要重新初始化

- **当前需求统计**:
  - 拆分子需求数量
  - 澄清问题数量(已解决/总数)
  - 计划改动文件数(新建/修改)
  - 已生成文件数
  - 测试覆盖情况

### 4. 资源文件清单
- PRD文档: `prd/original.md`
- 设计稿: `resources/images/`
- 技术文档: `tech/overview.md`, `tech/detailed-design.md`
- 改动点: `tech/change-points/`
- 代码日志: `code-changes.log`

### 5. 待办事项和问题
- 未解决的TODO项
- 待确认的问题列表
- 遗留的审查问题
- 建议的改进点

### 6. 下一步建议
根据当前状态提供操作建议:
- 需求处理完成 → 运行 `/spec.feat-tech` 开始技术方案设计
- 技术方案完成 → 运行 `/spec.code` 生成代码
- 代码生成完成 → 运行 `npm run dev` 检查 + `/spec.test` 生成测试
- 测试完成 → 运行 `/spec.review` 代码审查
- 审查完成 → 运行 `/spec.archive` 归档需求

## 快捷查看
- **完整状态**: `/spec.status`
- **仅进度**: `/spec.status --progress`
- **仅统计**: `/spec.status --stats`
- **仅待办**: `/spec.status --todo`

## 执行逻辑

### 1. 自动检测工作流
- 检查 `.spec/feature/` 目录下是否有工作流
- 检查 `.spec/bugfix/` 目录下是否有工作流
- 按修改时间排序，默认显示最新的工作流

### 2. 无工作流时的处理
如果没有找到任何工作流（`.spec/feature/` 和 `.spec/bugfix/` 目录不存在或为空）：

**显示提示信息**:
```
📊 工作流状态
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
ℹ️  当前没有活跃的工作流

💡 如何开始:
  - 新功能开发: /spec.auto 或 /spec.feat-prd
  - Bug 修复: /spec.bugfix
  - 初始化知识库: /spec.init

📚 知识库状态:
  - [根据 .spec/knowledge/ 显示知识库信息]
  - [如果没有知识库，提示需要先执行 /spec.init]
```

### 3. 有工作流时的处理
按照原有逻辑显示完整的工作流状态

## 注意事项
1. **无工作流时友好提示**: 明确告知用户如何开始工作流
2. **自动检测工作目录**: 无需手动指定，按时间排序
3. **准确读取状态**: 从实际文件系统读取，确保准确
4. **支持多工作流对比**: 可以同时查看多个工作流状态
5. **知识库状态检查**: 即使没有工作流，也显示知识库状态

## 与 /spec.utils.progress 的区别
- **/spec.status**: 面向用户的状态查看工具,提供可视化的进度展示和项目统计
- **/spec.utils.progress**: 底层进度持久化工具,由系统自动调用保存/恢复进度,支持断点续传

通常用户只需要使用 `/spec.status` 查看状态即可
