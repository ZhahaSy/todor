# 代码审查

对生成的代码进行规范性、安全性、性能和可维护性审查。

## 前置检查
读取代码生成报告、编码规范和文件列表

## 执行策略
启动3个Agent并行审查:
- Agent 1: 规范性 + 可维护性
- Agent 2: 安全性
- Agent 3: 性能

## Agent 1: 规范性与可维护性

### 审查清单
**命名**: 文件/组件/函数/变量/常量/类型/CSS类命名规范、描述性
**格式**: 缩进、引号、分号、行长度一致性
**导入**: 顺序正确、无未使用、无循环依赖、使用路径别名
**类型**: 函数和Props有完整类型、避免any、合理使用泛型
**注释**: 复杂逻辑有注释、公共函数有JSDoc、无过时注释和被注释代码
**结构**: 文件<300行、函数<50行、组件拆分合理、逻辑清晰、单一职责
**可维护性**: 无魔法数字、无重复代码、复杂度<10、易扩展易测试

### 输出格式
按优先级(P0/P1/P2)列出问题,包含文件位置、代码片段、问题说明、修复建议

## Agent 2: 安全性审查

### 审查清单
**XSS防护**: dangerouslySetInnerHTML转义、用户输入验证、URL参数验证、HTML转义
**注入防护**: SQL/命令注入防护、路径遍历防护
**认证授权**: 敏感操作权限检查、Token安全存储、无硬编码密钥
**数据安全**: 敏感数据不明文存储/打印、API密钥不写入代码
**依赖安全**: 无已知漏洞、版本合理

### 输出格式
按风险等级(High/Medium/Low)列出问题,包含文件位置、代码片段、风险说明、修复建议

## Agent 3: 性能审查

### 审查清单
**React性能**: React.memo/useMemo/useCallback合理使用、避免重渲染、列表key正确、大列表虚拟滚动
**网络性能**: API防抖节流、图片/组件懒加载、合理缓存
**数据处理**: 大数据优化、避免深层嵌套循环、算法复杂度合理
**内存管理**: 事件监听器/定时器正确清理、避免内存泄漏
**打包优化**: 按需导入、大依赖代码分割

### 输出格式
按优先级列出问题,包含文件位置、代码片段、性能影响、优化建议

## 汇总审查报告

生成 `.spec/feature/{YYYY-MM-DD}/code-review/review-report.md`:

**总体评分**: 规范性、安全性、性能、可维护性各维度评分和综合评分

**问题汇总表**: 按类型(规范/安全/性能)和严重程度(严重🔴/警告🟡/建议🔵)统计

**详细问题**: 按优先级(P0/P1/P2)列出所有问题、位置和修复建议

**上线建议**: ✅允许 / ⚠️条件允许 / ❌不允许

**后续行动**: 修复清单

## 自动修复
询问用户是否自动修复简单问题(如移除未使用导入、添加缺失类型等)

## 输出示例
```
✅ 代码审查完成
📊 审查{N}个文件, 约{M}行, 综合评分{X}/10
⚠️ 问题: 严重🔴{N}个, 警告🟡{M}个, 建议🔵{K}个
📝 报告: .spec/feature/{YYYY-MM-DD}/code-review/review-report.md
🎯 上线建议: {允许/条件允许/不允许}
💡 下一步: 修复严重问题后执行 /spec.archive 归档
📋 查看进度: /spec.status
```

## 注意事项
1. 启动3个Agent并行审查提高效率
2. 客观评价,给出具体可操作的修复建议
3. 优先级明确,考虑项目实际情况
