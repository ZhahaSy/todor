# 代码生成

基于技术方案详细设计生成实际项目代码。

## 前置检查

### 检测需求类型
1. **检查快速通道需求**: 读取 `prd/fast-track-approved.md` (如果存在)
2. **检查常规流程需求**: 读取 `tech/detailed-design.md` 和 `tech/change-points/`
3. **读取编码规范**: `coding-standards.md`
4. **读取 README**: 了解当前需求状态

## 执行步骤

### 0. 识别需求类型并分流处理

#### 0.1 快速通道需求处理

如果存在 `prd/fast-track-approved.md`:
1. 读取快速通道需求列表
2. 对每个快速通道需求:
   - 读取需求文档 (`prd/split/{功能名}.md`)
   - 读取相关的现有代码文件
   - 生成精确的代码改动清单
   - 应用改动(使用 Edit 工具精确修改)
3. 记录到 `code-changes.log`

**快速通道改动类型**:
- **文案修改**: 定位字符串常量,精确替换
- **样式调整**: 定位 CSS/样式代码,修改样式属性
- **UI微调**: 修改显示逻辑、条件渲染等
- **前端配置**: 修改配置文件、常量定义
- **静态资源**: 替换图片、图标文件

**快速通道处理原则**:
- 不涉及新建文件(除非替换静态资源)
- 使用 Edit 工具精确修改现有文件
- 改动范围小,影响面窄
- 无需复杂的依赖排序

#### 0.2 常规流程需求处理

如果需要处理常规流程需求:
- 继续执行步骤 1-7(完整的代码生成流程)

### 1. 准备工作(常规流程)
- 创建代码生成日志 `.spec/feature/{YYYY-MM-DD}/code-changes.log`
- 从 `tech/change-points/` 获取改动点列表
- 按依赖关系排序: types → constants → utils → services → hooks → components → pages → routes

### 2. 处理改动点

**新建文件**:
1. 确认目标目录存在
2. 提取完整代码
3. 检查格式(导入、类型、代码风格)
4. 使用 Write 工具创建
5. 记录日志

**修改文件**:
1. 使用 Read 读取现有文件
2. 分析改动点(末尾添加/具体行/特定函数后)
3. 使用 Edit 精确修改
4. 记录日志

**依赖导入**: 自动补充缺失的导入语句

### 3. 特殊文件
路由配置、菜单配置、导出文件等按需更新

### 4. 代码验证
检查语法、导入、类型、规范(命名、风格、文件大小)

### 5. 生成报告
创建 `code-generation-report.md`:
- 统计: 任务数、新建/修改文件数、代码行数
- 文件清单: 详细列表
- 目录结构变化
- 问题记录

### 6. 编译检查(可选)
尝试运行 `npm run type-check` 或 `npm run build`

### 7. 代码规范检查 (Lint)
生成代码后，运行 lint 检查确保代码符合规范：
1. 运行 `npm run lint` 检查代码规范
2. 如果有错误，运行 `npm run lint:fix` 自动修复
3. 对于无法自动修复的问题，手动调整代码
4. 提示用户检查修复结果

**注意**:
- 如果项目没有配置 lint，提示用户这是一个可选步骤
- 优先修复 lint 错误，警告可以暂时忽略
- 常见问题: 缩进、引号、分号、未使用变量等

## 注意事项

### 通用原则
1. 严格按改动点文档生成,保持代码一致性
2. TypeScript项目必须有完整类型定义
3. 合理注释、错误处理、性能优化、安全考虑
4. 及时记录日志,错误容忍继续处理
5. **生成代码后务必运行 lint 检查并修复所有错误**
6. 确保生成的代码符合项目的编码规范(缩进、引号、分号等)

### 快速通道特别注意
7. **快速通道改动必须精确**: 使用 Edit 工具精确定位和修改,避免影响无关代码
8. **文案修改**: 确保替换的是正确的文案位置,不要误改注释或其他字符串
9. **样式调整**: 只修改指定的样式属性,保持其他样式不变
10. **影响范围检查**: 快速通道改动虽小,但仍需确认不会破坏现有功能
11. **无需技术方案**: 快速通道需求直接从 PRD 文档读取改动要求,无需参考技术方案
12. **优先处理快速通道**: 如果同时存在快速通道和常规需求,优先完成快速通道改动
