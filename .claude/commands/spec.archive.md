# 需求归档与知识库更新

需求完成后归档文档并更新代码知识库,确保经验沉淀。

## 前置检查
确认代码审查完成,所有严重问题已修复

## 执行步骤

### 1. 收集归档信息
从 prd/、tech/、code-generation-report.md、test-report.md、code-review/ 中提取信息

### 2. 生成归档总结
创建 `archive-summary.md`:
- 需求基本信息(名称、类型、涉及系统、周期)
- 技术方案(技术选型、架构变更、技术难点)
- 代码产出(文件统计、清单、目录变化)
- 测试情况(统计、类型分布、通过率)
- 代码审查(评分、问题统计、遗留问题)
- 接口依赖和数据字典
- 工作量统计(预估vs实际)
- 经验总结(优点、改进、可复用方案、技术收获)
- 文档索引和相关链接

### 3. 更新代码知识库
更新 `.spec/knowledge/` 中的文档:
- **components.md**: 添加新组件(路径、功能、Props、示例、关联需求)
- **apis.md**: 添加新接口(方法、路径、参数、响应、位置)
- **functions.md**: 添加新函数(签名、功能、参数、返回值)
- **pages.md**: 添加新页面(路由、功能、依赖组件和API)
- **architecture.md**: 记录架构变更(如有)

### 4. 生成经验文档(可选)
如有值得记录的经验,创建 `.spec/knowledge/experiences/{YYYY-MM-DD}-{主题}.md`

## 输出示例
```
✅ 需求归档完成
📊 需求周期{X}天, 实际工作量{Y}小时
📁 新建{N}个, 修改{M}个, 总{K}行
✅ 测试覆盖{X}%, 通过{pass}/{total}
✅ 审查评分{Y}/10, 遗留{Z}个问题
📚 知识库更新: components+{N}, apis+{M}, functions+{K}, pages+{L}
📝 归档总结: archive-summary.md
🎉 本次需求已完成并归档!
📋 查看归档: /spec.status --history
```

## 注意事项
1. 确保所有步骤完成再归档
2. 归档信息准确,便于后续查询
3. 重点记录有价值的经验和可复用方案
4. 及时归档避免信息遗失
5. 知识库中标注关联的需求日期
6. 明确记录遗留问题和后续计划
