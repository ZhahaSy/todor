# 快速启动指南

5分钟快速上手 SDD AI 出码工作流

## 🎯 这份指南适合谁？

- ✅ 第一次使用本工作流的开发者
- ✅ 想快速了解基本用法的人
- ✅ 需要快速参考的老用户

## ⏱️ 预计时间

- **阅读本指南**: 5分钟
- **初始化知识库**: 2-5分钟
- **完成第一个需求**: 30-60分钟

## 📋 前置条件

### 必需

- [x] 已安装 Claude Code CLI
- [x] 有一个代码项目（新项目或现有项目都可以）

### 可选

- [ ] 准备一个PRD文档
- [ ] 准备Figma设计稿
- [ ] 了解你的技术栈

## 🚀 三步开始

### 步骤1: 进入项目目录

```bash
cd /path/to/your-project
```

### 步骤2: 启动 Claude Code

```bash
claude
```

### 步骤3: 初始化知识库

在 Claude Code 中执行:

```
/spec.init
```

AI会自动：
1. 扫描你的代码库
2. 分析项目结构
3. 生成知识库文档到 `.spec/knowledge/`

**耗时**: 2-5分钟

**完成标志**: 看到 "✅ 知识库初始化完成" 消息

## 🎓 第一个需求

完成初始化后，让我们完成第一个需求！

### 1. 启动需求流程

```
/spec.feat-prd
```

### 2. 提供PRD文档

AI会询问：`请提供你的PRD文档`

你可以：
- **直接粘贴**: 复制PRD文本粘贴
- **上传文件**: 提供本地文件路径
- **提供链接**: 提供在线文档链接
- **没有PRD**: 简单描述你的需求也可以

**示例**:
```
我需要开发一个用户登录功能，包括：
1. 用户名密码登录
2. 记住登录状态
3. 错误提示
```

### 3. 提供设计稿（可选）

如果有Figma设计稿，AI会询问：`是否有Figma设计稿？`

- 有：提供Figma链接
- 没有：回复 "没有" 或直接跳过

### 4. 回答澄清问题

AI会基于你的PRD提出一些澄清问题，例如：

```
🤔 我有以下问题需要澄清：

1. 用户名密码登录 - 是否需要支持第三方登录（如Google、GitHub）？
2. 记住登录状态 - 希望保持登录多久？（如7天、30天）
3. 错误提示 - 登录失败是否需要显示验证码？
```

**认真回答每个问题**，AI会根据你的回答生成明确的需求文档。

### 5. 确认需求文档

AI会生成澄清后的需求文档并询问：`请确认需求文档是否准确`

- 检查文档内容
- 有问题就提出修改
- 确认无误后回复 "确认"

**完成标志**: 看到 "✅ 需求文档已保存"

### 6. 设计技术方案

```
/spec.feat-tech
```

AI会询问：`这是新项目还是迭代项目？`

- **新项目**: 选择 "新项目"，AI会使用最新的最佳实践
- **迭代项目**: 选择 "迭代项目"，AI会遵循现有代码规范

然后AI会：
1. 分析需求
2. 读取知识库
3. 生成技术方案
4. 列出所有改动点
5. 为每个改动点生成代码片段

**检查改动点**: 确认要新建/修改的文件是否合理

**完成标志**: 看到 "✅ 技术方案已保存"

### 7. 生成代码

```
/spec.code
```

AI会根据技术方案自动生成所有代码。

**立即验证**:
```bash
# 退出Claude Code（Ctrl+D 或输入 exit）
npm run dev
# 或其他启动命令
```

检查：
- 项目能否正常启动
- 有无类型错误
- 核心功能是否工作

**如有问题**: 可以手动修改，或修改技术方案重新生成

### 8. 生成测试

```
/spec.test
```

AI会为生成的代码编写测试。

**验证测试**:
```bash
npm test
```

### 9. 代码审查

```
/spec.review
```

AI会并行审查代码的：
- 规范性
- 安全性
- 性能

**重点关注**: 🔴 标记的严重问题

**如有问题**: 修复后可以再次执行 `/spec.review`

### 10. 归档

```
/spec.archive
```

AI会：
1. 生成归档总结
2. 更新知识库
3. 记录经验教训

**完成标志**: 看到 "✅ 需求已归档，知识库已更新"

🎉 **恭喜！你已完成第一个完整的需求流程！**

## 📊 完整流程一览

```
/spec.init              # 首次：初始化知识库
  ↓
/spec.feat-prd          # 提供PRD，回答澄清问题
  ↓
/spec.feat-tech         # 选择项目类型，确认技术方案
  ↓
/spec.code              # 自动生成代码
  ↓
npm run dev             # 验证代码运行
  ↓
/spec.test              # 生成测试
  ↓
npm test                # 运行测试
  ↓
/spec.review            # 代码审查
  ↓
修复严重问题            # 如有
  ↓
/spec.archive           # 归档完成
```

## 💡 快速提示

### 需求阶段

✅ **提供完整信息**
```
好的PRD示例：
需求：实现用户登录功能
- 支持用户名密码登录
- 记住登录状态7天
- 登录失败显示错误提示

- 支持找回密码功能

❌ **信息不足**

不好的示例：

```

✅ **明确约束条件**
```
好的约束说明：
- 必须使用TypeScript
- 使用React Hooks，不用class组件
- 样式使用CSS Modules
- API请求使用axios
```

### 代码生成阶段

✅ **立即验证**
```bash
# 生成代码后立即运行
npm run dev

# 检查类型
npm run type-check

# 检查lint
npm run lint
```

### 审查阶段

✅ **重视严重问题**
- 🔴 严重：必须修复
- 🟡 警告：建议修复
- 🔵 改进：可选

## 🎯 使用场景指南

### ✅ 推荐使用本工作流

- 需求较复杂，需要仔细分析
- 涉及多个文件的修改
- 需要严格的质量控制
- 团队协作开发

**示例需求**:
- 新增完整的用户管理模块
- 实现复杂的数据可视化功能
- 重构现有模块

### ⚠️ 可选使用

- 中等复杂度功能
- 需求相对明确
- 个人项目

**示例需求**:
- 添加一个新的表单页面
- 实现一个数据列表
- 添加新的API接口

### ❌ 不推荐使用

- 简单的样式调整
- 文案修改
- 紧急Bug修复
- 快速实验

**示例**:
- 修改按钮颜色
- 更新文案
- 修复线上Bug

**这些情况**: 直接修改代码更快

## ❓ 常见问题

### Q1: 必须按顺序执行所有命令吗？

**A**: 建议按顺序执行以获得最佳效果，但也可以灵活调整：

- **可以跳过**: `/spec.test`、`/spec.review`（不推荐）
- **可以重复**: `/spec.code`、`/spec.review`
- **必须执行**: `/spec.init`（首次使用）

### Q2: 生成的代码有问题怎么办？

**A**: 三种处理方式：

1. **直接修改代码**（小问题）
   ```bash
   # 直接编辑文件
   vim src/components/Login.tsx
   ```

2. **修改技术方案重新生成**（方案有误）
   ```bash
   # 编辑改动点文档
   vim .spec/feature/{date}/tech/modifications/xxx.md
   # 重新生成
   /spec.code
   ```

3. **反馈给AI**（重大问题）
   ```
   生成的登录组件有问题：
   - 缺少错误处理
   - 状态管理不正确
   请帮我修复
   ```

### Q3: 如何处理需求变更？

**A**:

```bash
# 方法1: 修改现有需求文档
vim .spec/feature/{date}/prd/clarified/req-1.md

# 方法2: 添加新需求文档
# 在 clarified/ 目录下新建文件

# 重新执行后续流程
/spec.feat-tech
/spec.code
```

### Q4: 知识库什么时候更新？

**A**:
- **自动更新**: 每次执行 `/spec.archive` 时
- **手动更新**: 执行 `/spec.init` 重新初始化
- **建议**: 架构重大变更时手动更新

### Q5: 可以自定义工作流吗？

**A**: 可以！

```bash
# 查看命令定义
ls .claude/commands/

# 编辑现有命令
vim .claude/commands/spec.code.md

# 创建新命令
vim .claude/commands/spec.custom.md
```

### Q6: 团队如何协作？

**A**:

**共享知识库**:
```bash
# 提交知识库到Git
git add .spec/knowledge/
git commit -m "Update knowledge base"
git push
```

**独立开发流程**:
- 每个人独立执行工作流
- Feature目录可以独立管理
- 或者也提交Git便于Review

### Q7: 生成的代码质量如何？

**A**:
- 经过需求澄清、方案审查、代码审查三重保障
- 质量通常能达到85分以上（满分100）
- 但仍建议人工复查关键业务逻辑

### Q8: 支持哪些技术栈？

**A**: 理论上支持所有技术栈，已验证：
- ✅ React / Vue / Angular
- ✅ TypeScript / JavaScript
- ✅ Node.js / Python
- ✅ Next.js / Nuxt.js
- ✅ Express / Koa

### Q9: 需要什么编程水平？

**A**:
- 基础编程能力即可
- 了解使用的技术栈
- 能理解和验证生成的代码
- 无需深入掌握AI或复杂工具

**A**: 基于中等复杂度需求：

| 代码审查 | 1-2小时 | 5分钟 | ↑95% |
